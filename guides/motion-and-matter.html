Motion & Matter

How to make things move with intent in the browser, and how to build, light and direct 3D scenes there. Written for someone who already thinks in keyframes and key lights.

Each chapter explains the idea, then gives you a working bench where the real library runs. Change the controls until you can predict what will happen before you press play. When a chapter makes you want to build something, stop and build it. Reading teaches you the vocabulary, but your hands learn the timing.

Part I

Motion

GSAP from the ground up. Seven chapters that build on each other.

01What a tween actually is

Strip away the reputation and GSAP does one thing. It changes numbers over time. The word tween comes from cel animation, where a lead animator drew the key poses and assistants drew the in-betweens. A GSAP tween is that assistant. You give it a target, an end value, a duration and an ease, and on every frame it works out where the value should be and writes it.

The machinery is worth knowing exactly. The browser repaints about 60 times a second on most screens and 120 on high-refresh displays. GSAP runs a single clock, the ticker, built on requestAnimationFrame. On each tick, every active tween asks how much time has passed since it started. It divides that by its duration to get a progress number between 0 and 1. It passes that progress through the ease, then interpolates between the start and end values, then sets the property. Because the calculation starts from elapsed time and not from a frame count, a dropped frame never slows an animation down. The tween just lands a little further along on the next frame.

The bench below makes those frames visible. Every dot in the plot is one frame where GSAP wrote a new x value. Notice that the dots bunch up where the motion is slow and spread out where it's fast. Hold on to that picture, because the next chapter is about it.

The four verbs

      
gsap.to() animates from wherever the element is now to the values you give. It's the one you'll use most. gsap.from() is the reverse. It jumps the element to the values you give, then animates back to where it was. That's why it's the standard choice for entrances: you lay the page out in its final state in CSS, and from() brings each element in from somewhere else. gsap.fromTo() spells out both ends, which you want when the current state is unreliable, like when an animation can be interrupted and restarted. gsap.set() is a zero-duration tween. It applies values instantly, and it's how you prepare a starting state.


      
What you should animate

      
This matters more than any API detail. Changing transform (GSAP's x, y, scale, rotation) and opacity is cheap. The browser can move an already-painted layer on the GPU without recalculating the page. Changing width, height, top, left or margin forces the browser to redo layout every frame, and the page starts to stutter. If you think of it in compositing terms, transforms move a finished layer in the comp, while layout properties re-flow the document and re-render it. Award-level motion is almost always built from transforms and opacity, with clip-path and filters used sparingly.

      
GSAP also adds some conveniences. autoAlpha tweens opacity and sets visibility: hidden at zero, so invisible elements stop catching clicks. xPercent and yPercent move by a fraction of the element's own size. Relative values like "+=100" add to the current value. And the defaults are worth memorizing: if you don't specify them, duration is 0.5 seconds and ease is "power1.out".


      
Trap
from() renders its starting state the instant it's created, even if it has a delay or sits later in a timeline. This is deliberate, because it prevents a flash of the final layout before the animation starts. It surprises people when they stack two from() tweens on the same property, because the second one records the first one's start value as its destination. When you need to chain changes to the same property, use fromTo().

    


    

      
02Easing is the performance

      
If you remember one chapter, make it this one. An ease is a function that takes time progress (0 to 1) and returns value progress. Plot it with time running left to right and value running bottom to top. A straight diagonal is "none", constant speed, and it looks mechanical because nothing physical moves that way. Every other curve redistributes the same total distance across the same frames.

      
Animators already have words for this. Timing is how long a move takes and when it happens. Spacing is how the distance is divided between the frames. Two moves with identical timing can feel completely different because of spacing. The strip under the curve in the bench below is an animator's spacing chart. It shows the ball's position at 13 evenly spaced moments in time. Where the ghosts crowd together, the object is slow. Where they spread apart, it's fast. GSAP eases are spacing charts written as math.

In, out, and inOut

      
The suffix says where the ease does its work. An .out ease starts fast and decelerates into place. That's how things arrive: a card settling, a menu sliding in, a heading landing. An .in ease starts slow and accelerates away, which is how things leave. An .inOut ease speeds up and then slows down, which suits something moving from one place to another while staying on screen, like a camera move or a slider panning. A useful default that holds up most of the time is out for entrances, in for exits, and inOut for moves within the frame. Exits can usually be a bit shorter than entrances, because the eye has already lost interest in something that's leaving.


      
The families

      
The power eases are a ladder of strength. power1 is quadratic, power2 cubic, power3 quartic, power4 quintic. Each step up holds the motion back longer at one end and then commits harder at the other. expo is past power4, and sine sits below power1 and is very gentle. circ has a sharp knee near the end. Those are your everyday materials.

      
The character eases map to classical animation principles. back overshoots and settles, which is follow-through. Its .in version pulls backward before moving forward, which is anticipation. elastic wobbles like a spring and works for small playful accents, but it gets tiresome quickly when used on layout. bounce is literal, and it's rarely the right choice outside of something that is actually bouncing. steps(n) jumps in discrete increments, which gives you stop-motion and sprite sheets.


      
Why premium motion feels premium
Much of the motion on highly regarded sites uses a strong out-ease (expo.out, power4.out) with a longer duration than you'd expect, often around 1 to 1.6 seconds. The element leaves almost instantly, so the interface feels responsive, and then it spends most of its duration settling, so it feels weighty and calm. Try expo.out at 1.4s above, then power1.out at 0.4s. Both are fine. They describe different materials.


      
Duration, distance, and consistency

      
Treat these numbers as starting points rather than laws. Small interface responses like hovers and toggles feel right somewhere around 0.15 to 0.35 seconds. Panels and page elements moving a meaningful distance want 0.5 to 1 second. Hero and cinematic moments can run 1.2 to 2.5 seconds, but only when the viewer isn't waiting on them. Bigger distances need more time, and so do bigger objects, because we read size as mass.

      
Studios also pick a small set of eases and durations and use them everywhere. Two or three eases and three durations give a site a recognizable motion voice. In GSAP that's gsap.defaults({ ease: "expo.out", duration: 1.2 }) for the global default. When you need a curve the presets don't offer, the CustomEase plugin lets you draw one, and all of GSAP's plugins are free to use now.

    


    

      
03Timelines and the position parameter

      
A single tween is a move. A timeline is choreography. gsap.timeline() gives you a container that holds tweens on its own clock, and you control it as one object. It can play, pause, reverse, seek, change speed, or be scrubbed by scroll. If you've used the After Effects timeline, you already have the right mental picture. The bench even draws one for you.

      
By default, each tween you add starts when the previous one ends. That's tidy and it's also the main reason beginner animation looks robotic. Real motion overlaps. A head turns before the body finishes stepping. A title starts rising while its card is still settling. The tool for that is the position parameter, the optional last argument of every timeline method. Mastering it is most of what separates fluid GSAP work from stiff GSAP work.

There's a subtle difference between "-=0.3" and ">-0.3". The first measures from the end of the whole timeline so far, and the second from the end of the most recently added tween. They match until you place something out of order, and then they diverge. Use "<" and ">" when you're thinking about one tween relative to the one before it, which is most of the time.


      
How professionals structure big sequences

      
On a real site you don't write one timeline with sixty tweens. You write small functions that each return a timeline for one section, and you nest them in a master timeline. Nested timelines behave exactly like tweens, so the position parameter works on them too.

      
function intro() {
  return gsap.timeline()
    .from(".hero h1 .ch", { yPercent: 110, stagger: 0.04, duration: 1.2, ease: "expo.out" })
    .from(".hero .lede", { autoAlpha: 0, y: 20 }, "<0.4");
}
function nav() {
  return gsap.timeline().from(".nav a", { autoAlpha: 0, y: -10, stagger: 0.06 });
}

const master = gsap.timeline({ defaults: { ease: "expo.out", duration: 1 } });
master.add(intro())
      .add(nav(), "-=0.8")       // nav starts while the intro is still settling
      .addLabel("ready");

      
Two more tools belong here. defaults on a timeline sets duration and ease for every child, which keeps your motion voice consistent. And gsap.context() collects every tween and ScrollTrigger created inside it, so a single ctx.revert() kills them all and restores the original styles. That matters on sites with page transitions, in frameworks like React, and any time you rebuild an animation. The benches on this page rebuild their timelines whenever you move a control, and they rely on the same cleanup.

    


    

      
04Stagger: one idea, many objects

      
Pass GSAP an array or a selector that matches many elements and add stagger. Each element gets the same tween, offset in time. The simplest form is a number, stagger: 0.05, which means each element starts 0.05 seconds after the previous one. The object form is where the interesting design decisions live.

each sets the gap between consecutive elements, so total time grows with the number of elements. amount sets the total spread, so it doesn't matter whether you have 8 items or 800. Use amount when the element count can change, as with a CMS collection in Webflow. from decides where the wave begins: "start", "end", "center", "edges", "random", or a specific index. With grid set to "auto" or [rows, columns], GSAP measures distance in two dimensions, so a wave from the center ripples outward like water instead of running along a line. axis limits that measurement to columns or rows.

      
The ease inside the stagger object is easy to overlook and very expressive. It doesn't change how each element moves. It changes how the start times are distributed. With power2.in, the first elements start close together and later ones spread out, so the wave decelerates as it travels. With power3.out it's the opposite. Try both with the grid from the center and you'll see the ripple speed up or slow down as it expands.

      
Where you'll use it
Split headlines (letters or words staggered in), gallery grids, nav items, lists of features, particle fields, and, in Part III, a row of 3D objects. GSAP's SplitText plugin breaks text into lines, words and characters for you, and it's now free. The hero title on this page uses a hand-rolled version of the same idea.

    


    

      
05Following the hand: quickTo and smoothing

      
Much of what makes a site feel alive is how it responds to the pointer: a cursor follower that trails behind, a button that leans toward you, a 3D scene that shifts as your mouse moves. The underlying idea is always the same. You keep a target (where the pointer is) separate from the current value (where the thing is), and every frame you move current part of the way toward target. The lag is the feeling.

      
The classic way to write that is a lerp, current += (target - current) * 0.1, run every frame. It works, but it's tied to frame rate: on a 120Hz screen it catches up twice as fast as on a 60Hz one. GSAP's quickTo() solves this the time-based way. It creates one reusable tween for a single property, and every call retargets it without making a new tween. It's built for exactly this job, firing on every pointermove.

The two followers differ only in duration. The dot uses about a tenth of a second and feels attached. The ring uses whatever you set and feels like it's being pulled on a string. That pairing, one tight and one loose, is a common pattern, because the eye reads the gap between them as physical weight.

      
The magnetic button uses plain gsap.to() calls with overwrite: "auto". Each new call kills the conflicting part of the previous one, so you never get two tweens fighting over the same property. The label moves further than the button, a little parallax inside the object, and the release uses elastic.out so it snaps home with some life. This is one of the few places where elastic earns its keep.

      
Trap
Touch screens have no hover, so pointer effects should be enhancements, never the only way something works. Gate them with matchMedia("(hover: hover) and (pointer: fine)"), or better, with gsap.matchMedia() (covered in Chapter 12). Be careful about hiding the system cursor for a custom one. Juries and real users both notice when a creative cursor makes a site harder to use.

    


    

      
06Drawing with strokes

      
The line-drawing effect, where an illustration appears to be drawn by hand, is one of the oldest tricks in web animation, and it's worth understanding at the level of the underlying math because the trick generalizes. An SVG stroke can be dashed with stroke-dasharray. If you make a single dash exactly as long as the whole path, followed by a gap of the same length, the stroke looks solid. Then stroke-dashoffset slides that pattern along the path. Offset it by the full length and you're looking at the gap, so the line is invisible. Animate the offset to zero and the dash slides into place, drawing the line.


      

        
Bench 06 · a sprig, drawnsix paths, one stagger

const paths = document.querySelectorAll(".sprig path");
paths.forEach(p => {
  const len = p.getTotalLength();          // measured in SVG user units
  p.style.strokeDasharray = len;           // one dash the length of the path
  p.style.strokeDashoffset = len;          // slid fully out of view
});
gsap.to(paths, {
  strokeDashoffset: 0,
  duration: 1.4, ease: "power2.inOut",
  stagger: { each: 0.18 }                  // stem first, then each leaf
});

        

      


      
Once you've seen it this way, the effect becomes a material you can work with. You can draw from the middle outward, draw only a segment that travels along the path like a comet, or reverse the direction. GSAP's DrawSVG plugin handles all of that with friendlier syntax, like drawSVG: "40% 60%", and it deals with edge cases such as non-scaling strokes. MorphSVG, also free now, interpolates one path shape into another, which is how logos melt into icons. Learn the raw version first so you always know what the plugin is doing for you.

      
Trap
getTotalLength() returns the length in the SVG's own coordinate units. If you add vector-effect: non-scaling-stroke or scale the SVG unevenly, the dash lengths stop matching what you see on screen. Fills don't draw, only strokes do, so a filled illustration needs either an outline version or a clip-path or mask reveal.

    


    

      
07Scroll as a timeline scrubber

      
ScrollTrigger is the plugin behind most scroll-driven sites. It connects a region of the page to an animation, and there are only four ideas to master. A trigger is the element whose position you track. start and end say when the effect is active, each written as two words: a point on the trigger, then a point in the viewport. start: "top 80%" means "when the top of the trigger reaches 80% of the way down the viewport." And then you choose whether scrolling plays the animation or scrubs it.

Play versus scrub

      
Without scrub, the animation plays at its own speed when the trigger enters, and toggleActions decides what happens at the four crossing points. The string lists them in order: entering forward, leaving forward, entering back, and leaving back. "play none none reverse" means play once on entry and reverse only when scrolling back above the start. With scrub: true, scroll position is the timeline's progress, so the user's thumb becomes the playhead. A number like scrub: 1 adds smoothing: the animation takes one second to catch up to the scrollbar, which softens jerky trackpad and wheel input. That smoothing is a large part of why some scroll sites feel expensive and others feel twitchy.

      
Pinning

      
pin holds an element in place while the scroll continues, so the user scrolls through an animation rather than past it. ScrollTrigger adds padding (pinSpacing) so the content after it doesn't slide underneath. Pinned sections with a scrubbed timeline are the backbone of scroll-told product stories: the section freezes, the product rotates and parts label themselves, then the page releases and moves on. Turn on pinning in the bench with scrub set to true and watch the markers.

      
Trap
ScrollTrigger measures positions when it's created. If images, fonts or CMS content change the layout afterward, those measurements go stale, and things fire in the wrong place. Call ScrollTrigger.refresh() after late layout changes, and use markers: true during development so you can see the lines. Also be cautious with scroll hijacking. Smooth-scroll libraries like Lenis and GSAP's ScrollSmoother are popular on award sites, but taking control of native scrolling has real usability costs, and it's a deliberate design decision, not a default.

Push the field of view from 90 down to 12 with dolly turned on. The objects stay the same size in frame while the perspective flattens and the background seems to rush toward you. The setup every Three.js scene shares is short enough to memorize:

      
const renderer = new THREE.WebGLRenderer({ antialias: true, alpha: true });
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));   // cap at 2, see Chapter 10
container.appendChild(renderer.domElement);

const scene  = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(35, w / h, 0.1, 100);
camera.position.set(6, 3, 7);
camera.lookAt(0, 0.7, 0);

const sphere = new THREE.Mesh(
  new THREE.SphereGeometry(0.7, 64, 32),                       // radius, width & height segments
  new THREE.MeshStandardMaterial({ color: "#6f7f4a", roughness: 0.45 })
);
scene.add(sphere);

gsap.ticker.add(() => renderer.render(scene, camera));       // one clock for GSAP and Three

      
Wireframe mode shows the tessellation, and the triangle count tells you what the GPU is processing. Curved surfaces are approximations, and the segment counts in each geometry constructor control the trade between smoothness and cost. The sphere here uses 64 by 32 segments. That's generous for a hero object and wasteful for something small in the background.

    


    

      
09Light, material, and the real-time compromise

      
Your three-point lighting knowledge transfers directly. What has changed most since you last worked in 3D is the material model. Older renderers used Phong and Blinn shading, with specular color, specular size and glossiness set by eye. Modern real-time engines, Three.js included, use physically based rendering. MeshStandardMaterial describes a surface with a base color, a roughness from mirror-smooth (0) to fully matte (1), and a metalness that's usually either 0 (a dielectric like plastic, stone or wood) or 1 (a metal). The shading model conserves energy, so a rougher surface spreads the same reflected light over a wider highlight, and you rarely have to fight the material to look believable.

Three experiments to run on the bench

      
First, push sphere metalness to 1. The sphere goes dark and dull. That isn't a bug. A metal has no diffuse color of its own and shows only what it reflects, and this scene has no environment to reflect. That's why convincing metal on the web nearly always uses an environment map, usually an HDRI, loaded with RGBELoader and assigned to scene.environment. Environment lighting is also the single biggest quality jump you can give a real-time scene.

      
Second, turn the rim light to zero, then back up. Watch the silhouettes separate from the background. That's the same job rim lights did for you twenty years ago, and it matters even more on a web page, where the background is often a flat page color.

      
Third, switch tone mapping between ACES filmic and none, with the key light at 4. Without tone mapping, bright values simply clip to white. ACES compresses highlights the way film does, so a strong key reads as bright without burning out. Tone mapping, together with the correct color space (sRGB output, which this page sets), is the difference between a scene that looks like a render and one that looks like a cheap web demo.


      
Shadows are a second render

      
A real-time shadow is a shadow map. The renderer draws the scene a second time from the light's point of view, storing depth, and then checks each pixel against that depth map. That has consequences you can reason about. The map has a resolution (light.shadow.mapSize), so shadows get blocky when the shadow camera covers too large an area. Tighten the light's shadow camera bounds around your subject. A depth comparison that's too strict produces striped shadow acne, and the bias and normalBias settings fix it, but too much bias makes shadows detach from their objects, an artifact nicknamed peter-panning. Every shadow-casting light adds another render pass, so most polished scenes use one shadow-casting light at most.

      
How award sites get their lighting
Many of the most beautiful 3D sites aren't computing much lighting at all in the browser. The artists light the scene in Blender, bake the lighting and soft shadows into textures, and export the model as glTF. The browser then just displays pre-lit surfaces, which looks like an offline render and costs almost nothing per frame. Your background in offline 3D is directly useful here. The pipeline is Blender, then glTF (often compressed with Draco or Meshopt), then GLTFLoader in Three.js.

    


    

      
10The render loop and the frame budget

      
Offline rendering let you wait. Real-time rendering gives you a hard deadline, and every frame has to finish inside it, or the animation stutters. At 60Hz the whole frame, meaning your JavaScript, GSAP's updates, the browser's own work, and the GPU drawing your scene, has about 16.7 milliseconds. At 120Hz it has about 8.3. Most performance decisions in Three.js come down to protecting that budget.

      

        
CostWhy it's expensiveWhat professionals do

        
          
PixelsThe GPU shades every pixel. A 2× retina screen has 4× the pixels, and a 3× phone has 9×.Cap setPixelRatio at 2, or lower it adaptively when frames run slow.

          
Draw callsEach separate mesh and material is roughly one instruction batch for the GPU.Merge static geometry, and use InstancedMesh for many copies of one object.

          
Shadow mapsEach shadow-casting light renders the scene again.Use one shadow light, bake the rest, or fake contact shadows with a blurred texture.

          
Overdraw & transparencyLayers of transparent surfaces shade the same pixel many times.Keep transparency limited and use alpha testing for foliage-style cutouts.

          
MemoryGPU memory isn't garbage-collected for you.Call .dispose() on geometries, materials and textures you remove.

          
Hidden workA canvas below the fold still renders 60 times a second.Pause rendering when it's off screen, using IntersectionObserver.

        
      

      
Every 3D bench on this page follows those rules. Each caps its pixel ratio, renders only while visible, and draws from GSAP's ticker, so the motion clock and the render clock are the same clock. When something must be animated outside GSAP, like an idle rotation, multiply its speed by the frame's delta time (the seconds since the last frame) so it moves at the same real speed at 60Hz and 120Hz. The ticker hands you that value directly.

      
gsap.ticker.add((time, deltaMS) => {
  if (!visible) return;                       // set by an IntersectionObserver
  const dt = deltaMS / 1000;                  // seconds since last frame
  idleObject.rotation.y += 0.4 * dt;          // 0.4 rad per second at any refresh rate
  renderer.render(scene, camera);
});

// resize with the container, not the window
new ResizeObserver(() => {
  const { clientWidth: w, clientHeight: h } = container;
  renderer.setSize(w, h);
  camera.aspect = w / h;
  camera.updateProjectionMatrix();
}).observe(container);

      
Trap
Some visitors' devices can't create a WebGL context at all, or will lose it when memory is low. Wrap renderer creation in try/catch and design a real fallback, like a poster image or a video. Treat that fallback as part of the design, not an error message. Also, a note on versions: this page loads Three.js r149 because it's one of the last releases with a classic script build. Current releases are ES modules only (import * as THREE from "three"), and later versions renamed some color-management settings and changed the default light intensity units. Concepts here carry over, but check the migration notes when you copy settings into a modern project.

11GSAP as the director of a 3D scene

      
Here's the connection that makes everything above one craft. GSAP doesn't care what it animates. It tweens any numeric property of any JavaScript object. A Three.js mesh's position is an object with x, y and z. A light has intensity. A material's color has r, g and b. So gsap.to(mesh.position, { y: 2 }) just works. GSAP changes the number, and on the next frame the renderer draws the mesh in its new place. Timelines, eases, staggers and ScrollTrigger all come along for free.

The camera rig pattern

      
The camera isn't tweened directly. Tweening camera.position moves it in a straight line through space, which usually looks wrong, and you'd also have to keep re-aiming it. Instead the bench tweens a small plain object of abstract parameters, an orbit angle, a radius and a height, and every frame converts those into a camera position and a lookAt. Tweening the angle produces a true arc around the subject. That's the same idea as parenting a camera to a rotating null, and it's how most directed web cameras are built.

      
const rig = { angle: 0.35, radius: 7.5, height: 2.2, px: 0, py: 0 };

gsap.ticker.add(() => {
  camera.position.set(
    Math.sin(rig.angle) * rig.radius + rig.px,
    rig.height + rig.py,
    Math.cos(rig.angle) * rig.radius
  );
  camera.lookAt(0, 0.9, 0);
  renderer.render(scene, camera);
});

const tl = gsap.timeline();
tl.fromTo(rig, { angle: -1.1, radius: 11, height: 4.2 },
               { angle: 0.35, radius: 7.5, height: 2.2, duration: 3.2, ease: "power2.inOut" }, 0)
  .fromTo(key, { intensity: 0 }, { intensity: 2.4, duration: 1.6, ease: "sine.inOut" }, 0.2)
  .fromTo(slabs.map(s => s.position), { y: -1.2 },
          { y: 0.9, duration: 1.1, ease: "back.out(1.3)", stagger: { each: 0.12, from: "center" } }, 0.5)
  .fromTo(slabs.map(s => s.rotation), { y: -Math.PI / 2 },
          { y: 0, duration: 1.2, ease: "power3.inOut", stagger: { each: 0.12, from: "center" } }, "<0.35")
  .addLabel("accent")
  .fromTo(rim, { intensity: 0 }, { intensity: 3, duration: 1 }, "accent-=0.6")
  .to(centerSlab.material.color, { r: brass.r, g: brass.g, b: brass.b, duration: 0.8 }, "accent-=0.2");

      
Look at what's in that timeline. The stagger from Chapter 4 runs on an array of Vector3 objects instead of DOM elements. The position parameters from Chapter 3 overlap the camera move, the key light, and the slabs so they read as one gesture. The color tween animates a material's red, green and blue channels. Notice also that the camera uses inOut because it moves within the frame, while the slabs use back.out because they're arriving.


      
Pointer parallax, layered on top

      
The timeline owns angle, radius and height. The pointer owns px and py, through gsap.quickTo(rig, "px", { duration: 1.2, ease: "power3" }). Because they control different properties, they never fight, and the camera drifts with your hand even mid-reveal. Splitting control into separate channels that get added together is a pattern that scales: one channel for the authored animation, one for the user's input, and one for idle motion.


      
Driving it with scroll instead

      
Everything you scrubbed with the slider can be driven by scroll by adding one ScrollTrigger to the same timeline. This is how the "scroll through the product" sites are built.

      
ScrollTrigger.create({
  trigger: ".reveal-section",
  start: "top top",
  end: "+=2000",          // 2000px of scrolling plays the whole reveal
  pin: true,              // the canvas stays put while the story plays
  scrub: 1,               // one second of smoothing
  animation: tl
});

12What separates award-level work

      
It helps to know how the most visible jury judges. Awwwards, as far as I know, scores sites on design, usability, creativity and content, weighted roughly 40, 30, 20 and 10 percent. Check their current criteria before relying on that, but the shape of it is telling. Usability carries more weight than creativity. The sites that win are rarely the ones with the most effects. They're the ones where a single strong idea is carried through with consistency and the whole thing still works.

      
One idea, carried all the way through

      
Look at Ksenia's Paper Mono magazine. It's one idea: pages that bend like paper. Then she spent, in her words, a ridiculous amount of time on the deformation, layering lift, curl, waves and noise until it felt real. That's the pattern. Pick the most characteristic thing in your subject's world, make it the centerpiece, and keep everything around it quiet. For a GPU cloud, that might be something only a GPU can do in real time, rendered right there in the visitor's browser.

      
A motion language, written down

      
Studios write a motion spec the same way they write a type scale. It names a few eases, a few durations, and rules for entrances, exits and hovers. In GSAP you can encode it so it's enforced everywhere:

      
gsap.registerEase("arrive", gsap.parseEase("expo.out"));
gsap.registerEase("leave",  gsap.parseEase("power2.in"));
gsap.defaults({ ease: "arrive", duration: 1.1 });

const DUR = { quick: 0.25, base: 0.7, slow: 1.4 };   // three durations, used everywhere

      
Respect for the person on the other end

      
Some people get motion sickness from large movement, and they tell their operating system so. gsap.matchMedia() lets you write different animation for different conditions and automatically cleans up when conditions change:

      
const mm = gsap.matchMedia();
mm.add({
  full:    "(prefers-reduced-motion: no-preference)",
  reduced: "(prefers-reduced-motion: reduce)",
  fine:    "(hover: hover) and (pointer: fine)"
}, (ctx) => {
  const { full, reduced, fine } = ctx.conditions;
  gsap.from(".hero .ch", full ? { yPercent: 110, stagger: 0.04 } : { autoAlpha: 0, duration: 0.4 });
  if (fine) initMagneticButtons();
});

      
Reduced motion doesn't have to mean no motion. Fades and small changes in opacity are generally fine. Large translations, parallax, zooms and spinning are what to remove. The hero title on this page follows that rule.

      
Learning by taking things apart

      
The fastest way to develop taste is to study work you admire at a speed where you can actually see it. Open the browser console on a GSAP-built site and run gsap.globalTimeline.timeScale(0.2). Everything slows to a fifth of its speed, and you can watch the overlaps and eases (the slow-motion checkbox in the index does this to this page). Chrome's DevTools also has an Animations panel for CSS and Web Animations, and the Performance panel shows whether a site is keeping inside its frame budget. When something feels great, write down why in animator's terms: what eased, what overlapped, what anticipated.

      
Applying it in Webflow

      
GSAP and Webflow are now the same company, and Webflow has been building GSAP into its Interactions panel. How much you can do natively there changes quickly, so check the current state. For anything beyond it, load GSAP and its plugins in the site's custom code and write the code yourself, exactly as on this page. Three.js goes the same way: an empty div in the Designer as the container, the library from a CDN, and your scene script mounting into that div. Use Webflow's classes or data attributes as your selectors, and wrap everything in gsap.context() or gsap.matchMedia() so it cleans up properly.

    


    

      
13A practice plan

      
Mastery here comes from making many small things, each one targeting a specific skill, more than from reading. Ksenia built her reputation on unpaid, playful pens made between projects. The studies below are ordered so each one adds one new idea. Give each an evening or a weekend, keep them small, and post the ones you like. A body of small, finished experiments teaches more and gets noticed more than one large unfinished project.

Using AI as a studio partner
Given your aim of working AI-first, there's a productive way to pair it with this. Ask an AI model for a first-pass implementation of the mechanics, then spend your own time on the timing, the easing and the lighting. Those are the decisions that make work feel crafted, and they're the ones a jury notices. Asking the model to explain code it wrote in terms of the concepts here, such as the position parameter, spacing, and the camera rig, is also a fast way to make sure the understanding stays with you.
