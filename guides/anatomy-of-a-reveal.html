Anatomy of a Reveal

How the text and sections on three sites you admire actually come into view, read from their production code and rebuilt here as benches you can take apart.

This picks up where Motion & Matter left off. It assumes you're comfortable with tweens, eases, timelines and the basics of ScrollTrigger, and it goes deep on one subject: making type and sections arrive. Every value quoted from the three sites came from their live code on October 17, 2026. Sites change, so treat those numbers as a snapshot of good taste rather than a specification.

Part I

Forensics

What the three sites are really doing, and how to find out for yourself.

01Taking a site apart

Before building anything, it's worth knowing how I got the numbers in this guide, because the method is a skill you'll use for the rest of your career. I loaded each site in a headless browser, collected every JavaScript file it downloaded, and searched those files for the fingerprints libraries leave behind: license banners, class names like ScrollTrigger, option names like mask:"lines", and ease strings like "expo.out". Production code is minified, so variable names are scrambled, but strings, option keys and numbers survive. That's usually enough to reconstruct a recipe.

You can do a lighter version in any browser console. Open the site, then try these:

gsap?.version                       // is GSAP on the page, and which version?
ScrollTrigger?.getAll().length      // how many scroll triggers exist
gsap.globalTimeline.timeScale(0.2)  // slow every GSAP animation to a fifth
document.querySelectorAll("[aria-hidden] div, .char, .word").length  // split text?
// Many modern sites bundle GSAP privately, so window.gsap is undefined.
// Then search the Sources panel (Cmd+Opt+F in Chrome DevTools) for "ScrollTrigger",
// "SplitText", "lenis" or "onScroll".

What turned up

The three sites turned out to represent three different schools of thought, which makes them a better curriculum than three sites built the same way would have been.

The second and third columns already contain the most important idea in this guide. Scroll can play two different roles. It can be a trigger, a moment when a timed animation starts (Design is Funny). Choosing between those two roles is a design decision, and it changes how a site feels more than any ease or duration does.

Part II
Type
Splitting text into pieces, hiding them behind masks, and bringing them back.


    

      
02What splitting really does

      
You can't animate a single letter of a heading, because the letter isn't an element. Splitting fixes that by rewriting the heading's HTML so every line, word or character becomes its own element that can be moved. GSAP's SplitText, Anime.js's splitText and every hand-rolled version do the same three jobs.

      
The first job is breaking the text into words and characters. That sounds trivial, but modern splitters use the browser's Intl.Segmenter so emoji, accented letters and scripts like Thai don't get broken into garbage. The second job is detecting lines, and this is the clever part. Lines don't exist in HTML. They're whatever the browser decides when it wraps text to the container's width. So the splitter wraps every word in an element, measures each word's vertical position with offsetTop, and groups words that share a position into a line. That means line splitting depends on the font, the font size and the container width at the moment of measurement. The third job is accessibility. A screen reader reading thirty separate letter elements would spell the heading out, so the splitter puts the original sentence in an aria-label and hides the pieces from assistive technology.

Green outlines are lines, the underline marks each word, and alternating tints mark characters. Now narrow the container. With autoSplit: true, SplitText watches the element's width and re-splits when it changes, so lines regroup. The counter shows each re-split. That's the key fact about line splitting: it goes stale. Any animation you attached to the old lines now points at elements that no longer exist, which is why SplitText 3.13 added the onSplit callback. Return your animation from it, and SplitText rebuilds the animation on every re-split and even preserves its progress.

      
SplitText.create(".headline", {
  type: "lines, words",
  mask: "lines",            // wrap each line in an overflow: clip container
  autoSplit: true,          // re-split when fonts load or the width changes
  onSplit(self) {           // runs on every split; return the animation
    return gsap.from(self.lines, { yPercent: 100, stagger: 0.08, duration: 1.1, ease: "expo.out" });
  }
});

      
The mask option is the other big change in recent versions. It wraps each line, word or character in an extra element with overflow: clip. Look at the generated HTML under the bench with a mask on. You'll see each line wrapped in a sl-mask element. Masks are what make text appear to slide out from behind an invisible edge, which is the subject of the next chapter. Before masks were built in, everyone wrote that wrapper by hand.

      
Trap
Splitting before your web fonts load measures lines with the fallback font, which has different widths, so you get lines that break in the wrong places once the real font arrives. SplitText even warns about this in the console. Either split inside document.fonts.ready.then(...) or use autoSplit. Lusion splits with autoSplit: false and calls split() again manually inside its own resize handler, which is the same idea under its own control.

    


    

      
03The masked rise

      
The single most common text reveal on award-winning sites is a line or word rising from behind an invisible edge. It works because of a perceptual trick. A word that fades in is plainly appearing. A word that slides up from behind a hard edge reads as if it was always there, waiting below the surface. The mask gives the motion a horizon, and the horizon gives it weight. Everything else in this chapter is variation on that.

Reading the Design is Funny recipe

      
Here is the heading reveal from Daniele Buffa's site, as found in its code. It splits into words and characters and masks each word, but animates each character. Every character starts 60% of its height below its resting place, tilted back 70 degrees on the X axis around its bottom edge, and invisible. Over 2.5 seconds with expo.out, staggered 0.03 seconds apart, each one rises, swings upright and fades in. Turn on "show masks" and play it slowly with the slow-motion switch. The tilt is what makes it distinctive. Because each letter rotates around its baseline, it looks like it's being stood up from lying flat, more like a sign being raised than a word sliding.

      
The duration surprises people. Two and a half seconds is very long for text. It works because expo.out does almost all the travel in the first fifth of the time. The heading is readable within about half a second, and the remaining two seconds are a long, nearly imperceptible settle. That combination is a big part of the "premium" feeling on sites like this: fast to read and slow to rest.

      
The paragraph preset is the same site's recipe for running text. It animates whole words instead of characters, uses a smaller rise and a smaller tilt, and uses a much smaller stagger (the site uses 0.01 to 0.05 depending on the block), so a paragraph arrives as a soft wave instead of a typewriter effect. Larger text gets more drama, and smaller text gets less. That's a rule worth keeping.


      
Masks change the motion more than eases do

      
Try the classic line rise, then switch the mask from lines to none. Without a mask the lines slide up through the space where the line above them sits, so the motion looks like overlapping. With the mask, each line is clipped at its own baseline, so lines seem to emerge from slots. Now try masking by chars while animating chars: each letter rises in its own tiny window, which looks mechanical, like a split-flap display. The mask decides where the horizon is, and that's a compositional choice like cropping a photograph.

      
Trap
A mask clips everything outside its box, including descenders (g, y, p) and italic overhangs. In many fonts the line box is shorter than the glyphs, so the bottoms of letters get cut off in the final resting state. Turn on "show masks", pick lines, and look at the "y" in "really" and "weight". The standard fix is to add a little bottom padding to each mask and cancel it with a negative margin, so the layout doesn't move. That's what the "pad masks for descenders" switch does. Design is Funny solves the same problem by setting a custom line-height on its split words.

      
Small detail, big difference
Design is Funny gives every split character a rotation of 0.01 degrees. That tiny rotation forces the browser to render the character on the GPU with subpixel positioning, which stops letters from jittering by a pixel as they settle at the end of a long ease. Lusion does the same with translateZ(0) on its lines. You'll only notice the jitter on slow, long eases, which is exactly when it matters.

    


    

      
04Letters that roll

      
Both Design is Funny and Oryzo use the same hover effect on their navigation: the letters of a link roll upward and an identical copy rolls in from below. It's a split-text effect used for interaction instead of entrance, and it's a good example of how one technique can be reused.

Mechanically, each character is masked and given a clone of itself positioned directly underneath (top: 100%). Moving the character up by 100% of its height carries the clone into view while the original exits through the top of the mask. The defaults above are Design is Funny's exact values: a 0.012-second stagger, 0.7 seconds, expo.inOut. Their version stacks two full copies of the text. Lusion's LetterFlippers class appends a clone inside each masked character, which is the approach this bench uses.

      
Lusion adds one refinement worth copying. It checks which direction your pointer was moving when it entered, and rolls the letters starting from that side. With the checkbox on, enter a link from the right and the roll starts at the last letter. It's subtle, but it makes the effect feel like it responds to your hand rather than playing a canned animation. Turn it off and compare.

      
Trap
Keyboard users never hover. Bind the same effect to focus and blur (this bench does), and make sure the clone is hidden from screen readers. Otherwise a link reads its own name twice. SplitText's default aria: "auto" handles the split itself, but a clone you add by hand needs aria-hidden="true".

    


    
    
Part III
Scroll
The two roles scroll can play, and the smoothing that sits between your hand and the screen.


    

      
05Scroll as a trigger

      
Design is Funny's reveals follow one pattern, repeated on every block. A ScrollTrigger watches the block with start: "25% bottom" and once: true. When the point a quarter of the way down the block crosses the bottom edge of the viewport, the trigger fires one time, flips a piece of React state, and the reveal timeline plays at its own pace. The trigger then destroys itself. Scrolling back up does nothing, and scrolling down again doesn't replay it.

      
Each of those choices is deliberate. "25% bottom" waits until a meaningful slice of the block is visible, so the reveal happens where you're looking instead of at the very bottom edge where you aren't. once: true makes the reveal feel like the page settling into place, rather than a performance that repeats every time you pass. It also means a fast scroller who lands mid-page sees content that has already arrived. Replaying on every pass is the more common amateur choice, and it tends to make pages feel busy.

06Scroll as the clock

      
Lusion's approach is a different philosophy, and it's worth understanding in detail because it's how most of the very top tier of interactive sites work. There are no reveal tweens on Oryzo. Lusion's scroll manager measures each section's position on screen every frame and expresses it as a ratio. Then, for each character, it calls one small function, fit, that maps a slice of that ratio onto a property.

      
// Lusion's fit(), rewritten readably. It's a clamped range map with an optional ease.
function fit(value, inMin, inMax, outMin, outMax, ease) {
  let t = (value - inMin) / (inMax - inMin);   // where is value inside [inMin, inMax]?
  t = Math.min(1, Math.max(0, t));             // clamp to 0..1
  if (ease) t = ease(t);
  return outMin + t * (outMax - outMin);       // map onto [outMin, outMax]
}

// From Oryzo's hero, per character (i of n), every frame:
const e = i / (n - 1);                                   // 0 for the first char, 1 for the last
char.style.opacity   = fit(p, 0.5 + e * 0.2, 1.5 + e * 0.2, 0, 1);
char.style.transform = `translate3d(${fit(p, 0.5 + e * 0.2, 1.5 + e * 0.2, 1, 0, cubicOut)}em, 0, 0)`;
char.style.filter    = `blur(${blurAmount}em)`;           // blur is turned off on mobile layouts

      
Look at the input ranges. Every character gets its own window of the progress value. The first character's window starts at 0.5, the last one's at 0.7, and each window is 1.0 wide. That's a stagger, but expressed in scroll distance instead of time. Two numbers control the whole effect: the spread (how far apart the windows start) and the width (how long each character takes to complete). The bench draws every character's window as a bar, so you can see the stagger as a shape.

Spend a few minutes here, because these two numbers are a whole design vocabulary. Spread at zero makes every letter move together, like a single block fading in. A large spread with a small window makes letters appear one at a time, like typing. A small spread with a large window gives the soft, smeared wave Lusion uses, where many letters are in motion at once and each is at a slightly different stage. Turn the blur up and the wave looks like a camera pulling focus through the line.

      
Notice two more things in Lusion's code. Offsets are in em, so the motion scales with the type: a heading moves farther than a caption without separate settings. And the blur is switched off for the mobile layout, because CSS filter: blur() on dozens of elements is expensive and phones pay for it in dropped frames. That's a performance decision made at the level of a single property, which is the kind of care that separates studio work from tutorials.

      
When to choose the clock
Scroll-mapped motion is best when the content and the motion are one idea, when scrolling feels like moving through a space or operating a mechanism. It's a poor fit for ordinary reading content, because the reader controls the speed and a slow scroller sees half-formed words. Notice that Lusion uses it on short, display-sized lines, and that Design is Funny uses triggered tweens on its paragraphs. A common and effective approach is to mix them: scroll-mapped for the hero and set pieces, triggered for everything you're meant to read.

    


    

      
07Smoothing the input

      
Raw scroll input is ugly. A mouse wheel moves in discrete jumps, trackpads produce bursts with momentum, and touchscreens add their own inertia. If your animation is mapped directly to that signal, it inherits every twitch. All three sites smooth the input somewhere between the hand and the screen, and they do it in three different places.

      
Design is Funny smooths the scroll itself with Lenis, configured with a 0.75-second duration and an exponential ease-out (t => Math.min(1, 1.001 - Math.pow(2, -10 * t))). Lenis intercepts wheel input and animates the page's scroll position toward the target, so everything on the page, triggers included, sees smooth motion. Anime.js smooths the link between scroll and animation: sync: .9 on its observers means the animation chases the scroll position, with the number controlling how tightly. GSAP's version of that is a numeric scrub. Lusion smooths inside its own engine, with lerps and a class called SecondOrderDynamics, which is a spring-like follower that can overshoot and settle.

The plot shows each follower's progress over the last three seconds. Flick the scroll and watch the lines. The locked follower steps with every wheel tick. The 0.6 follower turns those steps into a curve. The heavy follower smooths so much that it lags well behind your hand. Smoothing is a dial between responsive and graceful, and too much makes a site feel disconnected, like steering a boat. Most polished sites land somewhere around a half second to one second of catch-up.

      
Trap
Don't stack smoothing layers without noticing. Lenis plus a numeric scrub means two smoothers in series, and their lags add together. If you use Lenis, scrub: true is often enough, because the scroll is already smooth. Also note that smooth-scroll libraries take over native scrolling, which affects anchor links, find-in-page, and some accessibility tools. Lenis handles most of these well, but it's still a decision to make deliberately.

08Choreographing a section load-in

      
A section entering is a small piece of choreography with a cast: an image, a kicker label, a heading, a rule, a paragraph, some metadata. The beginner move is to fade them all in together, or to stagger them in reading order with no overlap. The professional move is to give each member a role, sequence them by importance, and overlap them so they read as one gesture.

The counter-move curtain

      
The image reveal is taken from Design is Funny's project hovers. The image's outer frame slides up from below (yPercent: 100 → 0), while the picture inside slides down by the same amount (yPercent: -100 → 0) and scales from 1.3 to 1, both over one second with expo.inOut. Because the two movements cancel, the picture appears to stay still while a window opens over it. Turn off the counter-move and replay. Without it, the image just slides in as a card. With it, the image feels like it was already there, behind the page. It's the same principle as the masked text rise in Chapter 3, applied to an image.

      
Sequencing by importance

      
The order in the timeline isn't reading order. The image leads because it's the largest element and sets the stage. The kicker comes in early and quietly, giving context. The heading arrives with the most motion, character by character. The rule draws in to divide heading from body. The paragraph follows by lines, with less movement. The metadata simply fades up last. Each element's amount of motion matches its importance, and the overlap ties them together. Set overlap to zero and you'll see the same pieces arrive like a list being read aloud.

    


    

      
09Pinned beats and snapping

      
Some sections hold still while you scroll and tell a short story in place: a few statements replacing each other, a product turning, a diagram assembling. Lusion's Oryzo sections do this with their own math, mapping ranges like fit(r, 2.75, 3.5, 0, 1), where the numbers are measured in screen heights. GSAP's version is a pinned, scrubbed timeline with labels. The bench uses three beats of text that hand off to each other.

Labels are what make this structure work. Each beat ends at a named point in the timeline, and snap: "labelsDirectional" tells ScrollTrigger that whenever scrolling stops, it should glide to the nearest label in the direction the user was going. The user can never be stranded with two half-formed sentences on screen. Turn snapping off and stop scrolling mid-transition to see the problem it solves.

      
Look at the eases inside the hand-off too. The outgoing beat leaves with power2.in and the incoming one arrives with power3.out. That's Chapter 2 of Motion & Matter applied to type: exits accelerate away, and entrances decelerate into place. In a scrubbed timeline, eases still matter, because they shape how scroll distance is distributed across the motion.

      
Trap
Pinning changes the page's layout, because ScrollTrigger adds space so the content after the pinned section doesn't slide underneath. Create ScrollTriggers in the order they appear on the page, top to bottom, or call ScrollTrigger.sort(). A trigger created before a pin above it was measured without that extra space and will fire in the wrong place.

Trap
The threshold order is reversed between the two libraries, and it will catch you when you switch. ScrollTrigger's start: "top bottom" names the element's edge first and the viewport's second. Anime's enter: "bottom top" names the container's edge first and the target's second. I confirmed this in Anime's source rather than trusting memory. Both strings mean the same moment: the element's top reaches the bottom of the screen.

      
Trap I hit while building this bench
Anime's splitter measures lines only after document.fonts.ready resolves, so right after you call splitText(el, { lines: true }), the lines array is still empty. Animate it immediately and nothing moves, with only a console warning ("No target found") to tell you why. My first version of this bench made exactly that mistake. The fix is addEffect(): pass it a function that builds the animation, and Anime runs it once lines exist and again after every re-split, cleaning up the previous animation each time. It's the same idea as SplitText's onSplit.

      
Anime's sync deserves a closer look. The default, "play pause", is a trigger: it plays on enter and pauses on leave. true locks the animation to scroll like scrub: true. A number below 1 smooths the link, and in the 4.5 source that number sets how much of the gap is closed each frame. So lower numbers are smoother and heavier, which is the opposite direction from GSAP's scrub seconds. The Anime.js homepage uses .9, which is a light touch.

    


    
    
Part V
Craft
The details that decide whether reveals feel finished.


    

      
11Reveals that hold up

      
Never flash the final state

      
If your script runs after the page paints, visitors see the finished layout for a moment, then it vanishes and animates back in. That flash is the most common sign of an unfinished site. Design is Funny avoids it by keeping each text block hidden with CSS until its split is ready, then setting the container visible in the same moment it hides the characters: t.set(el, { autoAlpha: 1 }).set(chars, { autoAlpha: 0, ... }). The general pattern is to hide reveal targets in CSS (for example a .js-reveal { visibility: hidden } class added only when JavaScript runs), and let the animation un-hide them. Make sure content still shows if the script fails, or a broken CDN takes your whole site's text down with it.

      
Respect reduced motion without losing the content

      
Wrap your reveals in gsap.matchMedia(). For prefers-reduced-motion: reduce, replace rises, tilts and blurs with a short opacity fade, or show content immediately. Never leave elements hidden waiting for an animation that won't run. Anime.js's createScope({ mediaQueries }) does the same job.

      
Mind the cost of splitting

      
Every character becomes an element. A 40-word paragraph split into characters adds roughly 250 elements, and each one becomes a separate layer while it's moving. Split headings into characters, but split paragraphs into lines or words. Be especially careful with filter: blur(), which is one of the most expensive properties to animate. Lusion turns it off on mobile layouts entirely. Revert splits you no longer need, because split.revert() restores the original HTML and frees those elements.

      
Applying this in Webflow

      
Webflow's Interactions panel can run GSAP-based text and scroll effects natively now, and how much it covers changes quickly, so check the current state before deciding. For anything beyond it, the custom-code route works well: add GSAP, ScrollTrigger and SplitText in the site's custom code, mark reveal targets with a data attribute such as data-reveal="lines" in the Designer, and write one script that finds every marked element and builds the right reveal for it. That turns these recipes into a system your whole team can apply without writing code, which fits well with building tools that multiply a team's output. One Webflow-specific detail: wait for document.fonts.ready before splitting, because Webflow sites often load fonts asynchronously.

      
Using em for motion

      
Both Lusion (translate3d(1em, 0, 0)) and SplitText's percentage-based yPercent express motion relative to the type, not in pixels. That's what keeps a reveal looking the same at 18px and at 120px, and on a phone and a wide screen. Pixel offsets look heavy on small text and timid on large text.
